# Кошелёк Tabora: модель угроз и защитные меры

## Где живёт кошелёк
- Весь код кошелька выполняется в родительском процессе браузера как системный модуль
  (`WalletStore.sys.mjs`) и в chrome-документе окна (панель в ящике). Веб-страницы живут
  в изолированных контент-процессах и не имеют доступа ни к модулю, ни к DOM панели.
- Единственный мост для сайтов — провайдер (EIP-1193 и аналоги), который появится отдельным
  актором с узким набором сообщений. Родитель проверяет тип и форму каждого сообщения,
  привязывает запрос к origin и требует подтверждения пользователя на любую подпись.
- Акторы агента (чтение страниц, формы, медиа) работают только с контент-документами и не видят
  панель кошелька. У агента нет инструментов кошелька; системная подсказка запрещает ему
  запрашивать фразу или пароль.

## Секреты
- Seed-фразы хранятся только зашифрованными: AES-256-GCM, ключ из Argon2id (32 МБ, 3 прохода,
  соль 16 байт) от пароля. Файл `tabora-wallet.json` в профиле содержит публичные адреса,
  параметры KDF и шифртексты; расшифровать без пароля нельзя.
- В памяти, пока кошелёк разблокирован, хранится только мастер-ключ. Фраза расшифровывается
  на время деривации ключа и сразу обнуляется; приватный ключ существует только внутри
  операции подписи и обнуляется вызывающим кодом.
- Автоблокировка по таймеру (по умолчанию 15 минут бездействия) и вручную.
- Показ фразы: повторный ввод пароля, скрытие при потере фокуса окна и через 60 секунд,
  запрет копирования в буфер обмена.
- Режим без пароля допускается только после явного предупреждения: ключ хранится в менеджере
  паролей Firefox (NSS), панель постоянно помечает кошелёк как незащищённый.

## Криптография
- Никакой собственной криптографии: `@noble/hashes`, `@noble/curves`, `@scure/bip39`,
  `@scure/bip32`, `@scure/base`, `@scure/btc-signer` (аудированные библиотеки),
  версии зафиксированы в `tools/wallet-vendor/package.json`, сборка воспроизводима.
- Деривация проверяется на эталонной фразе BIP-39 (`WalletStore.selfTest()`):
  адреса совпадают с MetaMask, Phantom, TronLink и BIP-84.

## Сеть
- Публичные ноды по умолчанию, список и активная нода меняются пользователем. Запросы к нодам
  не содержат секретов; подписанные транзакции отправляются уже готовыми.
- Цены берутся из публичного API без идентификаторов пользователя и кэшируются.

## Подтверждения (следующий этап: отправка и провайдер)
- Любая подпись и отправка: панель подтверждения в chrome с расшифровкой: сеть, сумма,
  получатель, комиссия, разрешения токенов, предупреждения о неограниченных approve,
  о новых и похожих доменах (look-alike), о контрактах без верификации.
- Пароль запрашивается на каждое действие с ключами; таймер разблокировки не снимает это требование.

## Что не защищает
- Вредоносное ПО на самом компьютере с правами пользователя (кейлоггеры, снимки экрана).
- Утечку фразы, записанной пользователем вне браузера.

## Аудит 9 ноября 2026: что исправлено

- **Слепая подпись TRON.** Транзакции сайта декодируются из `raw_data_hex` (собственный protobuf-кодек); JSON `raw_data` от сайта не используется, `txID` пересчитывается, чужой `txID` и чужой владелец отклоняются. Собственные переводы TRX и TRC-20 собираются локально, у ноды берётся только ссылка на блок; перед подписью собранная транзакция сверяется с введёнными данными.
- **Solana `signMessage`.** Байты, которые разбираются как Message транзакции, не подписываются. Двоичные сообщения помечаются как опасные. Транзакции сайта разбираются по инструкциям (System, Token, Token-2022, ATA) с предупреждениями об approve, смене владельца, закрытии и сжигании; симуляция показывает изменение SOL и известных токенов. Парсер ограничен по размеру и количеству ключей/инструкций.
- **Листы подтверждения.** Кнопка включается через 0,5–0,9 с после показа, клики, начатые раньше, игнорируются; Enter срабатывает только после ввода пароля в этом листе; запрос сайта не забирает фокус. Листы сайтов ждут, пока закрыт любой другой лист, один ожидающий запрос на origin.
- **Границы для сайтов.** Только content-принципал по HTTPS (http для localhost); фоновая вкладка не может показать лист, пока пользователь её не откроет; запрос без предшествующего взаимодействия со страницей отклоняется; для фреймов показывается хост верхнего документа. Пока кошелёк заблокирован, адреса сайтам не отдаются.
- **EVM.** `nonce` сайта игнорируется, `chainId` сайта сверяется с сетью разрешения, calldata нормализуется (`data`/`input`), лимит approve предлагается только при известных десятичных и стандартной calldata; Permit (включая DAI-стиль и Permit2) показывает spender, лимит и срок. `wallet_watchAsset` предупреждает о совпадении символа с известным токеном.
- **Файл кошелька.** Открытая часть подписана HMAC-SHA256 на мастер-ключе; при расхождении показывается предупреждение, пока пользователь не подтвердит правки. Файл сохраняется с правами 0600. В сейфе хранится и seed (Uint8Array, обнуляется после подписи), фраза расшифровывается только для показа.
- **Отображение.** Невидимые и RTL-символы в сообщениях экранируются, направление текста изолировано. Ноды только по https.

## Известные ограничения

- Фраза при показе и пароль при вводе существуют в памяти как строки JavaScript: обнулить их нельзя, они живут до сборки мусора.
- Публичные ноды могут лгать о балансах, комиссиях и результатах симуляции; подписываемые данные от них не зависят (кроме ссылки на блок TRON и blockhash Solana, которые не влияют на получателя и сумму).
- Пользователь, вручную добавивший ноду, доверяет ей чтение своих адресов.

## Второй аудит 9 ноября 2026: что исправлено

- **TRON protobuf.** Декодер строгий: повтор любого одиночного поля, неизвестное поле, несовпадение `type_url` с типом, неподдерживаемый тип контракта или несколько контрактов — отказ. После разбора транзакция пересобирается каноническим кодеком, и байты обязаны совпасть с исходными: «показано одно, подписано другое» через нестандартную кодировку невозможно. Срок действия не больше суток, memo и permission показываются, нестандартное permission помечается опасным.
- **История.** События неизвестных токенов скрыты в любом направлении (контракт может эмитить переводы «от вашего имени»), цена считается только по встроенным токенам и монетам сети, свои токены без оценки. Десятичные знаки из любых источников ограничены 0..36. Хеши и адреса контрагентов проверяются перед сборкой ссылок и копированием.
- **Файл кошелька.** Обязательность подписи зафиксирована внутри зашифрованного блока `check` (версия v3), так что удалить подпись вместе с настройкой профиля нельзя. Запись файла в заблокированном состоянии запрещена, сайт не может вызвать ложную тревогу через `disconnect`. Канонизация идёт по сериализованному JSON.
- **EIP-712.** Опасные типы (TransferWithAuthorization, ForwardRequest, MetaTransaction, SafeTx, Seaport-ордера, Delegation и другие) помечаются и объясняются, подпись для другой сети отклоняется, контракт известного токена подсвечивается, формат v1 (массив) отклоняется заранее.
- **Очередь и активация.** Ожидание активной вкладки вынесено до постановки в очередь, фоновая страница не блокирует другие сайты; после отказа сайту нужен свежий клик (transient activation) в течение 30 секунд; очередь ограничена; методы чтения ограничены 60 запросами за 10 секунд на сайт; на каждом листе сайта есть «Отключить сайт и отклонить».
- **Листы.** Лист сайта живёт не дольше 2 минут и исчезает при блокировке кошелька; в режиме без пароля требуется реальное движение указателя внутри листа.
- **Solana.** В симуляцию включаются все токен-счета транзакции, принадлежащие пользователю (включая Token-2022 и не-ATA); уменьшение SOL без явного перевода, durable nonce, программы из таблиц адресов и lookups помечаются опасными.
- **Прочее.** «Неограниченный» approve с порога 2^96−1, подмена символа токена ловится по скелету похожих символов (кириллица, цифры) среди токенов всех сетей; строки из контрактов и API очищаются и ограничены по длине; направление текста изолировано во всех ячейках; контакты проверяются по формату адреса; при смене режима пароля ключ в менеджере паролей удаляется.

## Источники данных и приватность

- История операций запрашивается у публичных индексаторов: Blockscout (EVM), mempool.space (Bitcoin), публичная нода Solana, TronGrid (TRON). Эти сервисы видят ваши адреса и IP. Отключить можно, скрыв сеть в настройках.
- Фоновое наблюдение опрашивает балансы раз в минуту, в том числе при заблокированном кошельке (адреса публичны, фраза не нужна). Системные уведомления показывают суммы поступлений.
